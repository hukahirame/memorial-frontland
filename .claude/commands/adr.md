このセッションでの判断を振り返り、`docs/DECISIONS.md` に起票すべき候補を挙げてください。
$ARGUMENTS が指定されている場合は、その話題に絞ってください。

## 手順

1. `grep -n "^## \[D-\|^status:" docs/DECISIONS.md` で既存の見出しと status だけを取得する。
   全文は読まない。関連しそうな項目があるときだけ、その項目を読む。
2. `status: Proposed` の項目があれば、候補提示の前に一覧で示す。
   「保留中: D-XXX（タイトル）」の形式で1行ずつ。なければ何も言わない。
3. このセッションの会話から、下記の条件に当てはまる判断を抽出する。
   会話が短い場合のみ `git log --oneline -10` を補助的に見てよい。
4. 候補を提示し、AskUserQuestion で採否を尋ねる。
   **承認を得るまで `docs/DECISIONS.md` を編集しない。**

## 候補にする条件

いずれかに当てはまるもの。件数の上限は設けない。

- 何かを採用し、その代償（複雑さ・依存・学習コスト・後戻りの難しさ・容量・費用）を受け入れた
- 提案されたものを採用しなかった。「入れない」「今はやらない」も判断に含む
- 既存の [D-XXX] と矛盾する、または前提を覆す変更をした
- asmdef 構成 / CI / エージェント権限 / 公開範囲 / 外部サービスへの依存に触れた

## 候補にしないもの

該当するものは、単に挙げない。行き先の提案や、新しい仕組みの提案はしない。

- 代償なしに明らかに良い方（バグ修正、タイポ、素直なリファクタリング）
- 後から容易に変更できる実装の詳細
- 既に DECISIONS.md に同趣旨の記載があるもの
- 命名・書式・フォーマット
- Unity や Git の落とし穴、既知の不具合、ツールの一時的な挙動

## 品質基準

**却下案とその理由を書けない候補は挙げないでください。**
比較も代償も発生していない判断は、判断ではなく既定値です。

却下理由は、その場限りではなく**新しいケースにも一般化する形**で書くこと。
- 悪い例: 「今回は不要だったため」
- 良い例: 「6人規模では暗黙的解決の見通しの悪さが学習コストを上回るため」

## 出力形式

候補ごとに以下を提示する。ID は既存の最大値 + 1。欠番・再利用はしない。

```
## [D-XXX] （命令形のタイトル。何をするか）

status: Accepted
date: YYYY-MM-DD
tags: [architecture | infra | docs | agent | platform のうち該当するもの]
paths: [この決定が影響するパス。glob 可。なければ省略]
supersedes: D-XXX（既存を覆す場合のみ）

### 背景
何が問題だったか。既に固定されていた制約。
判断から自明な場合は省略してよい。

### 判断
命令形で1〜2段落。禁止事項があれば明示的に名指しする。
例: 「domain 層は UnityEngine を参照しない」

### 選択
- 却下した案 — 却下理由（一般化した形で）
- 却下した案 — 却下理由

### 帰結
新たに発生する作業、または明確に困難になることがある場合のみ書く。
なければ省略。
```

既存の D-XXX を覆す候補の場合は、
「D-XXX を `status: Superseded by D-YYY` に書き換える必要がある」ことも併記する。

## 採否の確認

候補を提示したあと、AskUserQuestion で採否を尋ねる。
候補1件につき1問。質問文には D-XXX のタイトルを入れ、どの候補への問いか分かるようにする。
選択肢は以下の3つ。

- **起票** — `status: Accepted` として追記する
- **保留** — `status: Proposed` として追記する。判断は次回以降に持ち越す
- **破棄** — 何もしない

保留中の項目は次回の `/adr` で必ず一覧に出るため、放置されない。
候補が0件のときは質問しない。

## 候補がない場合

「ADR 候補: なし」とだけ答える。
保留中の項目があればそれだけ示す。無理に挙げない。空振りは正常です。

## 禁止事項

- 会話の要約や作業ログを出さない。候補だけを出す
- 承認を得ずに `docs/DECISIONS.md` を編集しない
- 新しい CI チェック、AGENTS.md の制約、ドキュメントの追加を提案しない
- `docs/JOURNAL.md` を読まない。却下案や覆された前提が混在しており、採用済みと誤読する
