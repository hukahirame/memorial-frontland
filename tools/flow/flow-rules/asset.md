# asset — シーン・プレハブ・アセットの変更

## 前提: ここが一番の死角

YAML の差分は人間が読めず、LLM も意味を取れない。
この種別だけは、意図の検証手段が「人間が見る」しかない。

したがって**原則は、この種別の変更を減らすこと**。

- ロジックをシーンに置かない
- 参照をインスペクタで繋がず、コードまたは ScriptableObject に寄せる
- 変更がコードとアセットデータに現れるようにする

## 不変条件(機械が検証する)

アセット検証テストが通ること。

- 全シーン・全プレハブに参照切れ(Missing Reference)がない
- Missing Script がない

このテストがない場合は、先に作る。目視では検出できない。

## 手順

1. 変更する
2. アセット検証テストを実行する
3. 変更したシーン・プレハブのスクリーンショットを人間に提示する
4. **人間の確認を待つ**
5. コミットする

## SerializeField のリネーム

コード側でフィールド名を変えると、既存のシーン・プレハブの参照が切れる。

`[FormerlySerializedAs("旧名")]` を付けること。
付け忘れは参照切れとしてアセット検証テストで検出されるが、
値が消えた後では復旧できない場合がある。

このリネーム自体はコードの変更なので `refactor` だが、
アセットへの影響があるため、変更前に人間に報告する。

## プレハブの構造変更

ネストプレハブやバリアントの構造を変えると、影響範囲が読めない。
変更前に、どのプレハブに影響するかを調べて報告する。
