## デフォルトと違う点

- **いま保存は止まっている。** `Save()` は残っていて呼べば動くが、呼ぶ者が居ない。
  Domain 分割の間の措置
- 読み込みは起動時に 1 度だけ。`SaveSystem.Awake` でファイルがあれば読む。
  場所は移さず、始める側が `SaveSystem.SavedAreaId` を見てその場所から始める
- 保存先は 1 つ。`Application.persistentDataPath` の `.savedata.json`。枠を選べない
- 敵は「いま居る場所のぶん」しか持たない。設置物は場所ごとの控えをすべて持つ
- 保存した敵は、保存した根源に入ったときにだけ戻る。拠点で保存した敵は戻さない
  （攻め込んだ敵と同じく保存しない）。戻しても湧きの本数はいつもと同じ
- 立ち位置は、保存した場所に着いたときにだけ戻す。エディタで別の場所のシーンから始めると、
  その場所の決まった地点に立つ
- 設置物はアイテム ID で持つ

## 相互作用

- WHEN 保存があって起動した、保存した場所から始まり、着いたときに体力・所持金・経過秒・
  持ち物・立ち位置が戻る（[scene](scene.md)）
- WHEN 場所を離れた、設置物の位置が控えに書かれる（[scene](scene.md)）
- WHEN 場所へ入った、その場所の設置物が置き直される

## やらないこと

- 複数の保存枠
- 自動保存
- 根源とクエストの保存。`SaveData` に欄が無い

## 未決

- **根源とクエストが保存されない。** 攻略度も蓄積値も受注状態も再起動で消える。
  `JsonUtility` が `Root` と `Quest` の get-only プロパティを読めないため、
  DTO を挟む必要がある。`ItemSlot` で形は分かっている
- 保存を再開する契機。どこで `Save()` を呼ぶか
- 装備している武器は保存しない。読み込んだあとも、始めと同じ鉄の剣を持っている
- **Space キーを使わないこと。** 以前は保存キーがジャンプと同じで、
  跳ぶたびに保存されていた
- 保存の形が変わったときの互換。いまは版を持っていない
