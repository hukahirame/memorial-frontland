# Game Design Document 📘

> ⚠️ **削除予定。** このファイルは仕様を持たない。
> 「ゲーム仕様書をどう扱うか」の結論だけを残した記録。

## 方針 🧭

ゲーム設計は **Notion（個人 Wiki）** に置く。リポジトリには置かない。
柱とコアループは Notion のトップページ。

分厚い GDD は複数人のズレを防ぐための道具で、1人では防ぐべきズレが無い。
実際、Inventory と Craft の Domain 分離で仕様のすり合わせは起きたが、
着地したのはテスト名と ScriptableObject のフィールドで、GDD は要らなかった。

## 仕様はどこにあるか 🗂️

| 種類 | 正典 |
|---|---|
| 何のゲームか、柱、コアループ、世界観、敵やアイテムのロスター | Notion |
| 挙動 | テストコード |
| 数値 | ScriptableObject |
| 判断の理由 | `docs/DECISIONS.md` |
| 実装方法 | コード |

Notion での議論が**コードの形を決める**なら、その時点で `docs/DECISIONS.md` へ移す。
決めないなら Notion で完結させる。

## エージェントへ 🤖

Notion はリポジトリから見えない。
仕様が必要になったら**推測せず人間に聞く**こと。

## このファイルを消す条件 🗑️

チームが複数人になったら方針を見直す。
見直した結果まだ不要なら、このファイルを削除する。
それまでは「一度考えて置かないと決めた」印として残す。
